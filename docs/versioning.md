# Versioning

## Release Scope

`v0.1.0` includes:

- Multi-agent architecture
- Video content workflow skills
- Aesthetic scoring system
- Compliance and safety documentation
- Examples and documentation
- GitHub issue and pull request templates

## Versioning Approach

This project uses simple semantic versioning:

- Patch releases fix wording, documentation clarity, templates, and safety notes.
- Minor releases add new agents, skills, examples, workflows, or documentation sections.
- Major releases introduce breaking structural changes to the project workflow or public file layout.

## Public Release Safety

Every release should confirm that it does not include:

- Private evidence records
- Internal learning records
- Source audit logs intended for private use
- Reports or local project logs
- Output files or generated videos
- Data, assets, or materials with unclear authorization
- Platform credentials, API keys, tokens, cookies, secrets, or account data

## Release Checklist

Before publishing a release:

1. Confirm `git status` is clean.
2. Confirm the latest commit is pushed to `origin/main`.
3. Confirm the release tag points to the intended commit.
4. Confirm the release notes match `CHANGELOG.md`.
5. Confirm no private records, credentials, or unlicensed media are included.
